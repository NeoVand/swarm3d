# GPU neighborhood algorithms

This study distinguishes an acceleration structure, its GPU memory/traversal implementation, and a simulation model that changes which neighbors contribute. All three matter, but they have different correctness contracts. Measurements and final adoption results are recorded in [PERFORMANCE.md](./PERFORMANCE.md).

## What the old Swarm actually used

The current old engine constructs a uniform grid with GPU occupant counts, prefix offsets and scattered agent indices. Its “locally perfect hash” is a bijective block-major cell ordering: each 3×3 block stores its nine cells together. It retains all cells; it is not a compressed spatial hash. Cell width is half the global perception range. Index construction uses a work-efficient Blelloch scan, with 256 threads scanning 512 cells. See the old `src/lib/webgpu/compute.ts:430`, `buffers.ts:501`, `src/lib/shaders/count.wgsl:54`, and `prefix_sum.wgsl:54`.

The old working tree limits flocking and structure traversal to 64 occupants per cell, and directed and metric-rule traversal to 32. These are at `simulate.wgsl:718`, `:876`, `:1147`, and the structure pass. The retained HashFree implementation shifts each observer's query center within the same grid; indexing uses the unshifted positions. Fixed stencils, shifted query centers and occupant caps do not establish complete radius queries.

Historical commit `099d32c7cd281293bb1b8b0e60a8b9ab597afaea` contains five live modes in `src/lib/shaders/simulate.wgsl`. The selector/types were removed in `3fdbf05`; shader implementations were removed in `c013b93`.

No Morton/radix/bitonic state sort, shared-memory neighbor tiling, subgroup neighborhood reduction, BVH/octree, or reusable Verlet list was found in either the current engine or these historical five implementations. The old separate compact `vec2` position/velocity buffers are also substantially cheaper to read than complete 3D agent records.

## Current foundation and missing opportunities

Swarm3D already uses the GPU counting-sort class of index: count, prefix and scatter produce complete contiguous ranges per cell. All physical neighborhoods share one traversal; each completed resulting state is indexed again before measurement. Observer invocation order can follow the spatial index, while particle/history output slots retain identity. This foundation is closely related to the insert/prefix/copy pipeline used by [Hoetzlein's fixed-radius fluid solver](https://ramakarl.com/pdfs/2014_Hoetzlein_FastFixedRadius_Neighbors.pdf).

However, sorting indices alone leaves indirection into unsorted particle records, and cell-by-cell traversal repeatedly reads range headers. Rebuilding a correct grid is only one part of the performance problem. The active metric registry also matters: density needs neighbor membership/counts, alignment needs transported unit velocities, and anisotropy needs displacement moments. Computing all of them for every agent is unnecessary when most are unused.

## Candidate algorithms and decisions

| Candidate                            | Concrete application here                                                                                                                                                  | Correctness and cost gate                                                                                                                                                                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contiguous query strips              | Merge each contiguous X fragment into one index range for every queried Y/Z pair. Preserve primary/extra periodic fragment order.                                          | Same candidates, same final physical radius tests, same arithmetic order. Frozen outputs must remain bitwise identical.                                                                                                         |
| Proportional bin width               | Try half-width cells with the actual per-source query range and existing 65,536-cell limit.                                                                                | Include index rebuilds, extra headers/empty cells, all worlds and concentrated distributions. A smaller candidate volume can still cost more overall.                                                                           |
| Spatially packed hot records         | Scatter 32-byte position/velocity/species/identity records alongside stable original slot tags. Consume coherent neighbor records without moving persistent state/history. | Include gathering in the one resulting-state index rebuild per tick. Preserve selection, coincidence handling, per-neighbor metric lookup and species semantics. Stay within eight simulation storage bindings.                 |
| Cell-pair/workgroup tiling           | Split crowded observer cells into bounded chunks; cooperatively load neighbor tiles into workgroup memory and reuse them across observers.                                 | Requires a GPU work queue, conservative per-chunk ranges, uniform barriers even for inactive lanes, and accounting for partial tiles. Reduction order and register/occupancy costs must be measured.                            |
| Work-efficient prefix scan           | Replace Hillis–Steele cell scans with Blelloch or subgroup-assisted scans.                                                                                                 | Accelerates index construction only. Prioritize only when measured index cost is significant relative to queries.                                                                                                               |
| Reusable Verlet candidate lists      | Build with a skin radius and retain until displacement or configuration invalidates the list.                                                                              | Bound candidate memory in dense scenes; retain completed-state measurements, periodic/surface distances, range changes, obstacle/world changes and population migration.                                                        |
| LBVH/Morton or Hilbert cluster lists | Build a hierarchy or cluster candidate list for strongly nonuniform occupancy and heterogeneous ranges.                                                                    | Measure rebuild and traversal costs; retain exact final domain tests. This is a structural implementation, not a replacement justified by an algorithm name alone.                                                              |
| Aggregate range counting             | Count entirely contained cell/tree nodes from stored occupancy; descend or test individual agents only at the radius boundary.                                             | Promising for true count/density measurements. Arbitrary directed forces, observer-dependent surface transport and nonlinear weights need additional reasoning; count aggregation alone cannot replace their pair calculations. |

The strip/bin-width experiment is based on [Chisholm, Maddock and Richmond's FRNN study](https://eprints.whiterose.ac.uk/id/eprint/153625/). Its contiguous-strip construction applies directly to our X-major cell ranges. The paper's improvement claims are not transferred to this application; our frozen GPU experiments determine adoption.

**Adopted:** contiguous query strips. Across 99 controls, all five worlds, all behaviors, periodic fragments and coincident/inactive agents, physical outputs remained bitwise identical. Ordinary simulation dispatches improved roughly 6–30%, depending on the world and population; the 10,400-agent user fixture improved 10.5%. Grid width and the final radius tests remain unchanged.

**Rejected as a global default:** half-width cells. They improved ordinary 20k box index-plus-consumer work by about 16–19%, but made the dense 10k box roughly 38% slower. Sphere results were neutral or worse. The comparison used the same full-request diagnostic measurement variant, not the runtime's sparse metric specialization. A future distribution-aware strategy would need its own reliable decision and cost gate.

**Rejected:** 32-byte hot neighbor records. They passed 95 controls with four metric masks, but the complete production tick became 5.0–5.1% slower in ordinary 10k/20k boxes and 4.6% slower in a dense 5k box. Sphere improvements were only 0–3%. Timing includes simulation, one resulting-state index/scatter/gather, and measurement; the initial immutable index is prepared outside the timed tick. Production retains 4-byte neighbor indices.

[NVIDIA's tiled N-body implementation](https://developer.nvidia.com/gpugems/gpugems3/part-v-physics-simulation/chapter-31-fast-n-body-simulation-cuda) reuses shared particle data across multiple observer rows. That motivates dense cell-pair tiling. WGSL requires barriers in uniform control flow, so the current per-agent loops cannot simply acquire a barrier: their iteration counts and early exits differ. [WGSL uniformity rules](https://www.w3.org/TR/WGSL/#uniformity) govern the redesign.

The next dense-scene experiment should group occupied observer-cell chunks by source species and load contiguous neighbor tiles cooperatively. This avoids repeating neighbor memory traffic for each observer while keeping the current force laws. It requires a separate task-generation pass and kernel. Count/density aggregation is a separate opportunity for measurement passes; intrinsic surface bounds and observer-dependent transport need their own proof. Neither is implemented in production yet.

World-kind specialization replaces all 26 simulation geometry arguments with one bounded constant/helper. An initial timing run was superseded after the live preview was found running again; its timing claims are withdrawn. The final isolated integration audit, verified with the preview paused, improved ordinary box simulation 19.0% at 10k and 21.6% at 20k; sphere improved 11.5%/12.9%. Dense 5k box/sphere improved 12.9%/10.3%, and ordinary 5k plane/cylinder/torus improved 21.3%/21.6%/4.0%. Box/torus timing refers to their experimental fixed variants, not the retained generic production solver.

Across 80 controls plus nine timed fixtures, sphere/plane/cylinder matched bitwise. **Only these three fixed variants are adopted.** Box/torus failed the original strict bitwise gate and remain generic. All identities stayed exact; box differences affected only integrated XYZ positions (maximum absolute change `9.54e-7`), while torus changed position and transported velocities (maximum `3.815e-6`). Both passed the diagnostic's finite-output envelope, but that does not replace the original bitwise gate. The sentinel helper matched the original in all 89 cases. Reproduce with `node scripts/world-specialization-performance.mjs`; raw results and isolation timestamps are `.cache/world-specialization-performance.json`.

[HOOMD-blue's neighbor-list documentation](https://hoomd-blue.readthedocs.io/en/v2.5.2/nlist.html) compares cell, stencil and LBVH approaches and describes displacement-validated skin lists. Their relative value depends on cutoff asymmetry, distribution and list/rebuild cost. Swarm's directed rules also prevent assuming Newton-pair symmetry: observing species can use different behavior, strength and radius for the same pair.

The 2026 [GPU-native SFC cluster-list paper](https://arxiv.org/html/2602.19873v1) offers a more substantial path: spatially ordered clusters, per-cluster neighbor masks and compressed cluster indices. Its implementation uses CUDA/HIP, architecture-specific warp operations and an octree foundation. The cluster/reuse idea is relevant; its compression, allocator and published capacity figures are not a ready WebGPU integration or a capacity claim for Swarm3D.

## Benchmark contract

Run one GPU experiment at a time with other Swarm canvases paused. Alternate variants on frozen state, index and previous metrics; include ordinary and clustered populations, mixed species, all 12 behaviors, metric modes, long custom ranges, self-exclusion, coincident agents, inactive holes and periodic seams. Check all initial domains plus plane, cylinder and torus.

For changes preserving query order, require bitwise physical outputs and exact identity/counts. For structural sorting or cooperative reductions, report changed float words and establish a CPU/reference tolerance before adoption. Always time complete index-plus-consumer work, including payload gathering or candidate-list rebuilding. Rendering and evolved browser FPS are separate checks. An exact query structure reduces false candidates; a dense set of genuine nonlinear pair interactions still needs those interactions evaluated efficiently.

Historical bounded/stochastic modes remain potential explicit model choices. The initial complete solver will not silently switch to one when overloaded.
